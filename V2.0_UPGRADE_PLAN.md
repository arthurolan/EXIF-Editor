# V2.0 Upgrade Plan

## Product Positioning

V2.0 upgrades the project from a local JPEG EXIF editor into a local, lossless,
verifiable photo metadata editor and privacy cleaner.

The goal is to keep the directness and privacy of the current app, while making
metadata handling closer to professional tools such as ExifTool: accurate,
group-aware, conflict-aware, and explicit about risk.

## Why This Is V2.0

The current V1.0 product edits a focused set of EXIF fields for JPEG images. The
V2.0 work changes the core model of the app:

- From editing individual EXIF tags to editing semantic photo metadata.
- From JPEG-only handling to a planned multi-format metadata workflow.
- From a single metadata view to grouped EXIF, XMP, IPTC, MakerNotes, ICC,
  Photoshop, C2PA, and other metadata inspection.
- From simple field verification to format-aware image-data verification.
- From basic GPS removal to professional metadata privacy cleaning presets.

## Core Principles

### 1. Edit Semantic Fields, Not Isolated Tags

Users should edit concepts such as author, copyright, description, keywords,
capture time, camera, lens, and location. The app should translate those edits
into the appropriate EXIF, XMP, and IPTC tags.

Example: editing "Author" should not only write `EXIF:Artist`. It should also
write compatible XMP and IPTC fields where appropriate.

### 2. Detect Conflicts Instead Of Hiding Them

The app should detect when equivalent fields disagree across metadata standards.

Example:

- `EXIF:Artist` is `Alice`
- `XMP-dc:Creator` is `Bob`
- `IPTC:By-line` is `Charlie`

The UI should show a conflict and let the user choose which value to trust, or
enter a new value and unify all mapped fields.

### 3. Default To Compatible Synchronized Writes

Common editing should use safe semantic mappings by default. Advanced users can
still inspect grouped raw tags and perform more precise operations.

### 4. Keep Processing Local, Lossless, And Verifiable

All reading, editing, cleaning, and verification should remain in the browser.
Exports should be new files, not in-place overwrites. The app should verify that
the image data was not recompressed or unintentionally changed.

### 5. Be Honest About Metadata Risk

Some metadata groups are safe to edit. Others should be handled carefully:

- XMP and IPTC common fields are suitable for synchronized editing.
- MakerNotes should be displayed, but only edited through a strict whitelist.
- C2PA / Content Credentials should be warned about because edits may invalidate
  provenance verification.
- ICC profiles should not be removed silently because they may affect color
  appearance.

## Initial Semantic Field Mapping

| Semantic Field | Candidate Tags |
| --- | --- |
| Author | `EXIF:Artist`, `XMP-dc:Creator`, `IPTC:By-line` |
| Copyright | `EXIF:Copyright`, `XMP-dc:Rights`, `IPTC:CopyrightNotice` |
| Description | `EXIF:ImageDescription`, `XMP-dc:Description`, `IPTC:Caption-Abstract` |
| Title | `XMP-dc:Title`, `IPTC:ObjectName` |
| Keywords | `XMP-dc:Subject`, `IPTC:Keywords` |
| Date Taken | `EXIF:DateTimeOriginal`, `XMP-exif:DateTimeOriginal`, `XMP-photoshop:DateCreated`, `IPTC:DateCreated` |
| Camera Make | `EXIF:Make`, optional XMP TIFF namespace mapping |
| Camera Model | `EXIF:Model`, optional XMP TIFF namespace mapping |
| Lens | `EXIF:LensModel`, `XMP-exifEX:LensModel` |
| GPS Coordinates | `EXIF:GPS*`, `XMP-exif:GPSLatitude`, `XMP-exif:GPSLongitude` |
| Location Text | `XMP-photoshop:City`, `XMP-photoshop:Country`, `IPTC:City`, `IPTC:Country-PrimaryLocationName` |

This table is the first implementation target, not the final metadata schema.
Each mapping should be verified against ExifTool output and real files before it
is treated as stable.

## Proposed UI Structure

### 1. Common Metadata

The main editing surface for ordinary work:

- Author
- Copyright
- Title
- Description
- Keywords
- Date taken
- Camera make and model
- Lens
- GPS coordinates
- Altitude and direction
- Human-readable location fields

This section should use synchronized semantic writes by default.

### 2. Conflict Check

A dedicated view for contradictions between related EXIF, XMP, and IPTC tags.

Expected actions:

- Show all conflicting source tags.
- Let the user choose one value as canonical.
- Let the user enter a new value.
- Provide a one-click "unify" action.

### 3. All Tags Browser

A professional inspection view grouped by metadata family:

- EXIF
- GPS
- XMP
- IPTC
- MakerNotes
- ICC
- Photoshop
- C2PA / JUMBF
- File / Composite / Other

Default behavior should be read-only. Writable fields can expose edit controls
only when the app has a safe mapping or a clear advanced action.

### 4. Privacy Cleaner

Scenario-based cleaning presets:

- Privacy clean: remove GPS, serial numbers, device identifiers, thumbnails, and
  common processing traces.
- Social publish: keep author, copyright, title, description, and keywords;
  remove GPS, MakerNotes, serial numbers, and private device data.
- Preserve visual appearance: remove most metadata while keeping ICC color
  profiles and orientation-critical data where needed.
- Full metadata wipe: remove as much metadata as possible, with strong warnings
  about color, orientation, provenance, and compatibility.

Advanced cleaning should also allow explicit group deletion:

- `EXIF:All`
- `GPS:All`
- `XMP:All`
- `IPTC:All`
- `MakerNotes:All`
- `ICC_Profile:All`
- `Photoshop:All`
- `ThumbnailImage`
- `PreviewImage`
- C2PA / JUMBF-related data

## Supported Format Plan

V2.0 should keep JPEG as the most complete and best-tested format, then expand
support carefully.

| Format | Plan |
| --- | --- |
| JPEG | Full support. This remains the primary stable format. |
| PNG | Support metadata read, write, and clean. Note that PNG EXIF compatibility varies across apps. |
| WebP | Support EXIF, XMP, and ICC chunks where ExifTool can write them safely. |
| TIFF | Support with caution. Multi-page TIFF and large files need explicit testing. |
| HEIC / HEIF | Support metadata operations where ExifTool can write safely. Browser preview may be unavailable. |
| RAW | Out of scope for V2.0. RAW metadata and MakerNotes are too vendor-specific and risky for this release. |

## Preview Strategy

Preview should not be required for metadata work.

- JPEG, PNG, and WebP can usually use normal browser previews.
- HEIC may preview in Safari/macOS environments but should not be assumed.
- TIFF often will not preview in browsers.
- If preview is unavailable, show file information and metadata views instead.

## Architecture Direction

The current `app/page.tsx` contains reading, mapping, editing, diffing, writing,
and verification logic in one component. V2.0 should introduce a metadata layer
before adding major features.

Suggested modules:

- `app/metadata/types.ts`: shared metadata, group, conflict, and operation types.
- `app/metadata/schema.ts`: semantic field definitions and tag mappings.
- `app/metadata/read.ts`: ExifTool JSON parsing and ExifReader compatibility reads.
- `app/metadata/conflicts.ts`: conflict detection and canonical value selection.
- `app/metadata/write.ts`: semantic edits to ExifTool tag operations.
- `app/metadata/clean.ts`: privacy presets and group deletion operations.
- `app/metadata/verify.ts`: field and image-data verification.
- `app/metadata/formats.ts`: file format detection and format-specific behavior.

The existing Worker-based ExifTool write path should be kept, but generalized to
support parse operations, write operations, extra ExifTool args, and richer
results.

## Read Strategy

Use ExifTool JSON as the professional source of truth for V2.0:

- `-json`
- `-G1`
- `-a`
- `-s`
- numeric mode where useful for verification

ExifReader can remain useful for fast browser-friendly extraction and backward
compatibility, but the grouped metadata browser and conflict engine should be
built on ExifTool output.

## Write Strategy

The app should produce explicit ExifTool write operations from semantic edits.

Example author write:

```ts
{
  "EXIF:Artist": "Alice",
  "XMP-dc:Creator": ["Alice"],
  "IPTC:By-line": "Alice"
}
```

Example GPS removal:

```ts
{
  "GPS:All": "",
  "XMP-exif:GPSLatitude": "",
  "XMP-exif:GPSLongitude": ""
}
```

All writes should continue to export a new file rather than overwrite the
original.

## Verification Strategy

V2.0 verification should have three layers:

1. Re-read metadata after writing.
2. Verify changed fields and deleted groups.
3. Verify image data did not change unexpectedly.

Format-aware image-data verification:

- JPEG: verify compressed scan payload.
- PNG: verify image chunks such as `IDAT`.
- WebP: verify image data chunks such as `VP8`, `VP8L`, or `VP8X`.
- TIFF: verify conservative structural invariants and rely on ExifTool
  non-reencoding behavior where direct image-data comparison is not simple.
- HEIC / HEIF: verify file structure conservatively and rely on ExifTool
  non-reencoding behavior where necessary.

If a format cannot be verified as strongly as JPEG, the UI should say so
clearly.

## MakerNotes Policy

MakerNotes should be treated as high-risk metadata.

V2.0 should support:

- Displaying MakerNotes in the all-tags browser.
- Deleting MakerNotes as part of privacy cleaning.
- Editing only through strict, camera-brand-specific whitelists after testing.

V2.0 should not provide arbitrary MakerNotes editing.

## C2PA / Content Credentials Policy

The app should detect C2PA / JUMBF / Content Credentials metadata where possible.

Behavior:

- Warn that metadata edits may invalidate verification.
- If cleaning removes C2PA data, show that provenance metadata will be removed.
- Do not imply that the exported file remains content-credential verified after
  metadata changes.

## Implementation Milestones

### V2.0 Alpha

- Add metadata types and semantic schema.
- Add ExifTool JSON parsing in the Worker.
- Build grouped metadata model.
- Implement conflict detection for author, copyright, description, title,
  keywords, date, and GPS.
- Keep existing JPEG editing behavior working.

### V2.0 Beta

- Add synchronized EXIF / XMP / IPTC writes for common fields.
- Add conflict resolution UI.
- Add all-tags grouped browser.
- Add privacy cleaning presets.
- Add verification for synchronized writes and deleted groups.
- Add initial PNG and WebP support.

### V2.0 Release Candidate

- Add TIFF and HEIC / HEIF support where reliable.
- Add format-aware image-data verification.
- Add MakerNotes display and deletion.
- Add stronger C2PA warnings.
- Expand test fixtures and regression tests.

### V2.0 Stable

- Stabilize supported format matrix.
- Polish UI copy and risk warnings.
- Complete tests for representative real-world files.
- Update README and release notes.

## Testing Plan

Use real sample files where possible:

- Camera JPEG with EXIF and MakerNotes.
- iPhone JPEG with EXIF, XMP, GPS, and possible C2PA/JUMBF data.
- Lightroom or Photoshop exported JPEG with XMP/IPTC fields.
- JPEG with conflicting EXIF/XMP/IPTC author and copyright.
- PNG with XMP and ICC profile.
- WebP with EXIF/XMP/ICC chunks.
- TIFF with metadata and, if possible, a multi-page TIFF.
- HEIC with metadata and no guaranteed browser preview.

Automated tests should cover:

- Semantic mapping output.
- Conflict detection.
- Cleaning preset operations.
- Post-write metadata verification.
- Format detection.
- Format-specific image-data verification where practical.

## Open Questions

- Which exact ExifTool tag names should be canonical for each semantic field
  after testing across Lightroom, Photoshop, Apple Photos, Windows Photos, and
  common DAM tools?
- Should "preserve visual appearance" keep orientation metadata, or normalize
  orientation only when the app can prove image data remains unchanged?
- Which MakerNotes fields, if any, are safe enough for V2.0 editing?
- Should HEIC support be marked experimental until enough samples are tested?
- Should the app expose an ExifTool-style advanced command preview before export?

## Non-Goals For V2.0

- RAW file support.
- Arbitrary MakerNotes editing.
- Server-side file processing.
- In-place overwrite of original files.
- Pixel editing or image recompression.
