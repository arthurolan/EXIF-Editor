# 影刻·EXIF

隐私优先的本地照片元数据编辑器。照片的读取、修改、隐私清理与验证都在浏览器中完成；原片不会上传或被原地覆盖。

## V2.1：安全批处理

已支持对最多 100 张、总计不超过 1 GB 的图片进行**逐张串行**隐私清理、GPS 删除或批量文字写入。批量文字写入支持作者、版权、关键词、城市和国家/地区；仅填写的字段会同步写入兼容的 EXIF、XMP 和 IPTC 标签，空字段保持每张照片原值。每一项都会独立读取、写入、重新读取元数据并核验图像数据；失败或核验未通过的项目不会影响其他项目，且不会提供下载。队列保留逐项状态、失败原因和“仅重试失败项”入口；已验证副本可逐张下载，或一次打包为 ZIP 下载。Chromium 浏览器还可选择文件夹，其他浏览器可直接多选文件。

批量时间偏移已支持：可为每张照片的原始拍摄时间统一增加或减少天、小时、分钟，并逐项写入和核验。缺少可解析拍摄时间的文件会单独失败且不交付。批量 GPS 写入也已支持：可直接填写经纬度，或主动加载与单张编辑相同的地图后点选位置；统一写入 WGS‑84 经纬度，海拔与拍摄方向可选；每张导出副本都会重新读取并比对坐标后才交付。

批量过程显示完成进度、当前文件与处理阶段，结束时播放提示音（取决于浏览器音频许可）。HEIC / HEIF 批量文字写入仅支持作者和版权；关键词、城市、国家/地区保持原值并在结果中明确提示，不影响已通过核验副本的交付。

2026-09-06 至 2026-09-07，用户已确认文件夹及多选入口、50 张图片处理与完整下载、隐私清理及序列号删除、批量文字、时间偏移测试通过。2026-09-07，HEIC / JPG / PNG / TIF / WebP 混合图片按地图选点写入 GPS，用户复查未发现差错。这是已测试样本的验收记录；TIFF、HEIC / HEIF 的实验性格式限制仍然适用。

完整版本说明与回退方法见 [CHANGELOG.md](CHANGELOG.md)。

## 格式支持（沿用 V2.0）

| 格式 | 状态 | 说明 |
| --- | --- | --- |
| JPEG | 稳定支持 | 读取、语义同步写入、冲突检查、隐私清理和 JPEG 扫描数据校验。 |
| PNG | 实测通过 | 支持读取、写入、删除 GPS、隐私清理、保留视觉外观与彻底清空；导出后校验 `IDAT` 图像数据。不同应用对 PNG 元数据的兼容性可能不同。 |
| WebP | 实测通过 | 支持读取、写入、删除 GPS、隐私清理、保留视觉外观与彻底清空；导出后校验 `VP8` / `VP8L` 图像数据并忽略 `VP8X` 容器标志变化。 |
| TIFF | 实验性支持 | 支持经典单页 TIFF 的读取、常用字段写入和清理；多页 TIFF、BigTIFF 与无法识别 Strip/Tile 图像数据的文件暂不进入编辑流程。导出后校验图像数据区。 |
| HEIC / HEIF | 实验性支持 | 支持可识别 HEIF 容器的读取、写入和标准元数据清理；浏览器预览不作保证。导出后复核容器与 `mdat` 数据存在；由于 EXIF 本身可位于 `mdat` 中，不提供像素级哈希承诺。含 HDR、景深或人像辅助图像的文件会保留其必要 XMP/ICC，不能执行彻底清空或删除 ICC。 |
| RAW | 不支持 | V2.0 非目标，避免高风险的厂商私有元数据修改。 |

V2.0 会同步常用 EXIF、XMP 和 IPTC 字段，并提供冲突检查、按组删除、隐私清理预设及导出后复核。MakerNotes、ICC 色彩配置和 Content Credentials 属于高风险数据：默认只读或需要明确选择删除。

TIFF 和 HEIC / HEIF 仍保持“实验性”标记；若写入工具或导出复核失败，应用会阻止下载。请始终保留原文件。

## V2.0 实测状态

2026-09-03，使用 WebP、相机 PNG 和 Midjourney PNG 样本完成回归：

- 有 GPS 的 WebP / PNG：`位置 → 删除位置` 与 `按组删除 → 删除 GPS` 均可导出；导出文件重新导入后无经纬度。
- 无 GPS 的 WebP / Midjourney PNG：可添加 GPS。
- PNG / WebP 清理预设：隐私清理、保留视觉外观、彻底清空均可导出，未发现回退。

## 本地开发

需要 Node.js 22 和 pnpm 10。

```bash
pnpm install
pnpm dev
```

`pnpm build` 会在 `out/` 生成可部署到任意静态托管服务的文件，`pnpm test`
会执行构建，并运行格式识别、语义映射、冲突检测、隐私清理和静态产物回归测试。

## GitHub Pages

推送到 `main` 后，[Deploy GitHub Pages](.github/workflows/deploy-pages.yml)
工作流会：

1. 自动识别用户站点（`<owner>.github.io`）或项目站点的路径；
2. 生成带正确子路径和公开地址的 Next.js 静态导出；
3. 验证 HTML、社交分享图和 WebAssembly 文件；
4. 发布到 `github-pages` 环境。

也可以在 GitHub 的 **Actions** 页面手动运行该工作流。首次发布前，仓库的
**Settings → Pages → Build and deployment → Source** 应设为 **GitHub Actions**。
